# 데드락 (Deadlock)

## Deadlock Problem

- 일련의 프로세스들이 서로가 가진 자원을 기다리며 block된 상태
- **Resource**
  - 하드웨어, 소프트웨어 등을 포함하는 개념 (I/O device, CPU, memory, semaphore 등)
  - 프로세스가 자원을 사용하는 절차: request → allocate → use → release

## 발생 조건 (4가지 모두 만족해야 발생)

- **Mutual exclusion (상호 배제)**: 매 순간 하나의 프로세스만이 자원을 사용할 수 있음
- **No preemption (비선점)**: 프로세스는 자원을 스스로 내어놓을 뿐 강제로 빼앗기지 않음
- **Hold and wait (보유 대기)**: 자원을 가진 프로세스가 다른 자원을 기다릴 때 보유 자원을 놓지 않고 계속 가지고 있음
- **Circular wait (순환 대기)**: 자원을 기다리는 프로세스 간에 사이클이 형성됨

## 처리 방법

| 방법 | 내용 |
|---|---|
| **Prevention** | 4가지 필요 조건 중 하나가 만족되지 않도록 자원을 할당 |
| **Avoidance** | 자원 요청에 대한 부가 정보를 이용해 deadlock 가능성이 없을 때만 할당 |
| **Detection and recovery** | 발생은 허용하되 detection 루틴을 두어 발견 시 복구 |
| **Ignorance** | 시스템이 책임지지 않음. 사용자가 직접 프로세스를 종료 |

- UNIX를 포함한 대부분의 OS는 **Ignorance**를 채택한다. deadlock은 자주 발생하지 않기 때문에 방지를 위해 오버헤드를 들이는 것이 비효율적이기 때문

## Deadlock Prevention

- **Mutual Exclusion**: 공유해서는 안 되는 자원의 경우 반드시 성립해야 하므로 깨기 어려움
- **Hold and Wait**: 자원을 요청할 때 다른 자원을 가지고 있지 않아야 함
  - 프로세스 시작 시 필요한 모든 자원을 할당받는 방법 → 비효율
  - 자원이 필요하면 보유 자원을 모두 놓고 다시 요청하는 방법
- **No Preemption**: 자원을 기다려야 하면 이미 보유한 자원을 선점당함
  - 필요한 자원을 모두 얻을 수 있을 때 다시 시작
  - 상태를 쉽게 저장하고 복원할 수 있는 자원(CPU, memory)에서 주로 사용
- **Circular Wait**: 모든 자원 유형에 할당 순서를 정하고 정해진 순서대로만 할당

## Deadlock Avoidance

- 자원 할당이 deadlock으로 이어질 가능성이 있는지 사전에 판단해 안전한 경우(safe)에만 할당
- 일반적으로 각 프로세스가 필요로 하는 자원의 최대 사용량을 미리 선언하게 한다
- **Safe state**: 시스템 내 모든 프로세스에 대해 safe sequence가 존재하는 상태 (현재 남은 자원만으로 모든 프로세스를 끝낼 수 있는 상태)
- **Safe sequence**
  - 시퀀스 `<P₁, P₂, …, Pₙ>`이 safe하려면 `Pᵢ`의 자원 요청이 **가용 자원 + 모든 `Pⱼ (j < i)`의 보유 자원**으로 충족되어야 함
  - 그러면 다음 방법으로 모든 프로세스의 수행을 보장할 수 있다
    - `Pᵢ`의 요청이 즉시 충족되지 않으면 `Pⱼ (j < i)`가 모두 종료될 때까지 기다림
    - `Pᵢ₋₁`이 종료되면 `Pᵢ`의 요청을 만족시키고 수행
