# 컴퓨터 시스템 구조 Part 2

## 입출력 (I/O) 방식

### 동기식 입출력 (Synchronous I/O)

- **특징**: I/O 작업이 완료될 때까지 사용자 프로그램은 실행을 중단하고, CPU 제어권은 OS로 넘어감
- **동작 과정**
  1. 사용자 프로그램이 시스템 콜을 호출
  2. OS가 I/O 요청을 처리하며 해당 프로세스를 Block 상태로 전환
  3. OS는 해당 프로세스를 I/O 대기 큐에 넣고 다른 프로세스에게 CPU를 할당
  4. I/O 장치가 작업을 완료하면 하드웨어 인터럽트 발생
  5. OS는 해당 프로세스를 Ready 상태로 전환
  6. 스케줄러에 의해 CPU가 재할당되면 프로세스 실행이 재개됨

### 비동기식 입출력 (Asynchronous I/O)

- **특징**: I/O 요청 후 제어권을 즉시 사용자 프로그램에 반환하고, I/O는 백그라운드에서 처리
- **동작 과정**
  1. 시스템 콜로 I/O 요청 → 제어권 즉시 복귀
  2. 사용자 프로그램은 I/O 완료를 기다리지 않고 다음 작업 수행
  3. I/O 완료 시 인터럽트 발생 → 등록된 콜백 함수 실행 또는 이벤트 큐에 등록

## 프로그램 실행 및 메모리 구성

- 프로그램 실행 시 프로세스마다 독립적인 가상 주소 공간이 생성되고 할당됨
- 각 프로세스의 주소 공간은 0번지부터 시작
- 해당 프로세스가 메모리 전체를 사용하는 것처럼 보이게 함
  - 다른 프로세스의 메모리 영역을 침범하지 못하도록 보호하여 시스템의 안정성 확보

### 주소 공간 구성

- **코드 (Text)**: 실행 코드(명령어) 저장, 읽기 전용
- **데이터**: 전역/정적 변수 저장
  - 초기화된 데이터: `.data` 영역
  - 초기화되지 않은 데이터: BSS 영역
- **스택**: 함수 호출 정보(지역변수, 매개변수, 반환주소) 저장
- **힙**: 런타임 중 동적 할당된 메모리 저장 (`new`, `malloc` 등)

### 메모리 관리와 가상 메모리

- **커널**: 부팅 시 메모리에 상주, 시스템 종료까지 유지
- **사용자 프로그램**: 필요한 코드와 데이터만 메모리에 적재, 나머지는 디스크 스왑 영역에 위치
- **페이징**
  - 가상 주소 공간을 페이지 단위로 나누어 메모리나 스왑 영역에 매핑
  - 페이지 폴트: 접근한 페이지가 메모리에 없는 경우 → 디스크에서 해당 페이지 로드
- **MMU (Memory Management Unit)**
  - 가상 주소를 물리 주소로 변환하는 하드웨어
  - 페이지 테이블을 참조하여 매핑 수행
  - TLB (Translation Lookaside Buffer): 최근 주소 변환 결과를 캐싱하여 속도 향상

## 커널 주소 공간

- **코드 영역**
  - 시스템 콜 처리 루틴: I/O, 프로세스 생성/종료 등
  - 인터럽트 서비스 루틴 (ISR): 하드웨어 인터럽트 발생 시 처리
  - 운영체제 핵심 기능 코드: CPU 스케줄링, 메모리 및 파일 시스템 관리, 장치 드라이버 등
- **데이터 영역**
  - PCB (Process Control Block): 프로세스의 상태, 레지스터 정보 등
  - 자원 관리 정보: CPU, 메모리, 디스크 사용 현황
  - 운영체제 큐: 준비 큐(Ready Queue), I/O 대기 큐 등
- **스택 영역**
  - 커널 스택: 시스템 콜 및 인터럽트 처리 시 사용
    - 프로세스별로 독립적인 커널 스택이 할당
    - 사용자 스택과 분리되어야 커널 코드가 보호되고 안정성 유지
- **힙 영역**
  - 커널 모듈, 버퍼, 구조체 등 다양한 내부 데이터 구조 관리
