# 프로세스 동기화 기법

## 동기화

- 멀티 프로세스(스레드) 환경에서 프로세스 간의 **실행 순서**나 **공유 자원에 대한 접근(상호 배제)을 제어**하는 것

### 경쟁 상태 (Race Condition)

- 여러 개의 프로세스가 공유 자원에 동시에 접근하여 발생하는 문제
- 데이터의 최종 연산 결과는 마지막에 그 데이터를 다룬 프로세스에 따라 달라짐
- 예) 계좌 입출금

![데이터의 접근](./images/sync-1.png)
![Race Condition](./images/sync-2.png)

- OS에서 race condition이 발생하는 경우
  - 커널 수행 중 인터럽트 발생 시
  - 프로세스가 시스템 콜을 하여 커널 모드로 수행 중인데 문맥 교환이 일어나는 경우
  - 멀티프로세서에서 공유 메모리 내의 커널 데이터에 접근하는 경우

### 임계 영역 (Critical Section)

- 공유 자원을 사용하는 코드 영역
- 하나의 프로세스가 임계 영역에 있을 때 다른 모든 프로세스는 임계 영역에 들어갈 수 없어야 한다

### 상호 배제 (Mutual Exclusion)

- 공유 자원에 동시 접근을 제어하는 것

### 상호 배제의 조건

- **상호 배제 (Mutual Exclusion)**: 한 프로세스가 임계 영역에 있으면 다른 프로세스는 진입할 수 없음
- **진행 (Progress)**: 임계 영역에 프로세스가 없을 때, 임계 영역에 진입하려는 프로세스는 진입할 수 있어야 함
- **유한 대기 (Bounded Waiting)**: 진입을 요청한 후 허용될 때까지 다른 프로세스들이 먼저 들어가는 횟수에 한계가 있어야 함 → 기다리는 시간이 유한해야 함

## 동기화 기법

### 뮤텍스 (Mutex)

- 공유 자원에 대한 동시 접근을 제어
- 이진 상태(잠금/해제)를 가진 객체
- 상태를 업데이트하기 위해 lock(acquire)과 unlock(release) 함수 사용
  - **lock**
    - 프로세스가 임계 영역에 접근하기 전에 호출
    - 잠금 상태라면 해제 상태가 될 때까지 대기
    - 해제 상태라면 잠금 상태로 바꿈
  - **unlock**
    - 프로세스가 임계 영역에서 작업을 끝내면 호출
    - 상태를 해제로 바꿈

### 세마포어 (Semaphore)

- 정수 값을 가진 변수(카운터 S)와 연산(P, V)으로 구성
  - **P (wait) 연산**
    - 카운터가 1 이상이면 임계 영역에 접근하고 카운터 값을 감소시킨다.
    - 카운터가 0 이하면 임계 영역에 접근을 제한한다.
  - **V (signal) 연산**: 카운터 값 증가
- 공유 자원이 여러 개 있는 상황에 적용 가능
- **Counting semaphore**: 0 이상의 임의의 정수값. 주로 자원 개수를 세는 데 사용
- **Binary semaphore (= mutex)**: 0 또는 1값만 가짐. 주로 상호 배제(lock/unlock)에 사용
- 하드웨어적 해결 방법으로 Test-and-Set 같은 원자적 명령어도 있다

### 구현 방식

**바쁜 대기**

```java
// 카운터 변수
int S = initialValue

// P 연산 (wait)
function wait(int S) {
  while (true) {
    if (S > 0) {
      S = S - 1;
      return;
    }
    // 자원 없음 - 바쁜 대기로 계속 시도
  }
}

// V 연산 (signal)
function signal(int S) {
  S = S + 1
}
```

**블로킹**

```java
// 대기 중인 프로세스 큐
Queue waitQueue = new Queue()

// P 연산 (wait)
function wait(int S) {
  // 자원 카운터 감소
  S = S - 1

  if (S < 0) {
    // 사용 가능한 자원이 없음
    // 현재 프로세스를 대기 큐에 추가
    waitQueue.add(currentProcess)
    // 대기 상태로 전환
    sleep(currentProcess)
  }
}

// V 연산 (signal)
function signal(int S) {
  // 자원 카운터 증가
  S = S + 1

  if (S <= 0) {
    // 대기 중인 프로세스가 있음
    if (!waitQueue.isEmpty()) {
      // 대기 큐에서 하나 꺼내서 깨움
      process = waitQueue.remove()
      wakeup(process)
    }
  }
}
```

### 모니터 (Monitor)

- 공유 자원과 이에 접근하기 위한 인터페이스(연산, 프로시저)를 묶어서 관리하는 기법
- 프로세스는 프로시저를 통해서만 공유 자원에 접근 → 캡슐화
- 모니터 내 프로시저는 한 번에 하나의 프로세스만 실행 → 상호 배제
- 진입 큐를 사용해 모니터에 진입하려는 프로세스들을 순차적으로 처리
- 프로그래머가 lock을 직접 걸 필요가 없고, 동기화 제약 조건을 명시적으로 코딩할 필요가 없음
- 세마포어의 문제점을 보완하기 위한 고수준 동기화 도구
  - 세마포어는 코딩하기 힘들고, 정확성 입증이 어렵고, 한 번의 실수가 시스템 전체에 치명적
- 조건 변수: 프로세스가 모니터 안에서 기다릴 수 있도록 하기 위한 변수
  - 대기 큐: wait 연산으로 중단된 프로세스들이 대기하기 위한 큐 (진입 큐와 다름)
  - wait: 프로세스를 대기 상태로 전환하고 대기 큐에 삽입
  - signal: 대기 상태의 프로세스 중 정확히 하나를 깨워 실행 (대기 중인 프로세스가 없으면 아무 일도 일어나지 않음)

## 고전적인 동기화 문제

### Bounded-Buffer Problem (생산자-소비자)

- 생산자: 빈(empty) 버퍼를 찾아 데이터를 채움
- 소비자: 찬(full) 버퍼를 찾아 데이터를 꺼냄
- 공유 데이터: 버퍼 자체 및 버퍼 조작 변수

### Readers-Writers Problem

- 한 프로세스가 DB에 write 중일 때 다른 프로세스가 접근하면 안 됨
- read는 동시에 여러 프로세스가 해도 됨
