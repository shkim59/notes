# 프로세스

## 프로세스 (Process)

- 실행 중인 프로그램
- 메모리에 적재되어 CPU를 할당받아 명령을 수행하고 있는 상태

### 프로세스의 문맥 (Context)

CPU가 특정 프로세스를 수행하는 데 필요한 모든 정보의 집합

- **하드웨어 문맥**: 현재 CPU가 어떤 작업을 하고 있는지 나타내는 정보
  - Program Counter (PC): 다음에 실행할 명령어의 메모리 주소
  - Register: 연산에 필요한 데이터를 임시 저장하는 CPU 내부 고속 저장 공간
- **프로세스의 메모리 구조**: 프로세스가 접근할 수 있는 가상 메모리 공간
  - Code: 프로그램의 실행 코드
  - Data: 전역 변수, 정적 변수 등
  - Stack: 함수 호출 시 지역 변수, 매개변수, 리턴 주소 등
- **커널 자료 구조**: 운영체제가 각 프로세스를 관리하기 위해 유지하는 정보
  - PCB (Process Control Block)
  - Kernel Stack: 시스템 콜이나 인터럽트 발생 시 커널 코드 실행에 필요한 정보 저장

### 프로세스의 상태

- **New**: 프로세스가 생성되고 있는 초기 상태. 아직 메모리 적재나 자원 할당 전
- **Ready**: 메모리에 적재되고 CPU를 기다리는 상태 (Ready Queue에서 대기)
- **Running**: CPU를 할당받아 명령어를 수행하고 있는 상태
- **Blocked (Wait, Sleep)**: CPU를 할당받더라도 당장 명령어를 수행할 수 없는 상태. I/O 완료, 이벤트 발생 등을 기다림 → 이벤트가 발생하면 Ready로 전환
- **Terminated**: 실행이 완료되거나 오류로 종료된 상태. 모든 자원을 반납

## PCB (Process Control Block)

프로세스를 관리하기 위해 프로세스당 유지하는 정보를 담은 자료 구조

- **OS 관리 정보**: 프로세스 상태, 프로세스 ID(PID), 스케줄링 정보(우선순위, 스케줄링 큐 포인터 등)
- **CPU 수행 관련 하드웨어 값**: 문맥 교환 시 저장/복원될 PC, 레지스터 값
- **메모리 관련 정보**: Code/Data/Stack 영역의 주소와 크기, 페이지 테이블 또는 세그먼트 테이블 정보
- **파일 관련 정보**: 열려 있는 파일 디스크립터, 파일 포인터 등
- **I/O 상태 정보**: 할당된 I/O 장치, 보류 중인 I/O 요청 목록 등

## 문맥 교환 (Context Switch)

- CPU를 한 프로세스에서 다른 프로세스로 넘겨주는 과정
- 비용이 많이 드는 작업이므로 너무 자주 발생하지 않도록 관리하는 것이 중요
- 수행 내용
  - CPU를 내어주는 프로세스의 상태를 해당 프로세스의 PCB에 저장
  - CPU를 새롭게 얻는 프로세스의 상태를 PCB에서 읽어와 CPU 레지스터에 적재

## 스케줄링을 위한 큐

- **Job Queue**: 시스템 내에 존재하는 모든 프로세스의 집합 (Ready Queue, Device Queue 포함)
- **Ready Queue**: 메모리에 적재되어 CPU를 기다리는 프로세스의 집합. 단기 스케줄러가 다음 실행할 프로세스를 선택
- **Device Queue**: 특정 I/O 장치의 처리를 기다리는 프로세스의 집합

## 스케줄러

- 프로세스들에게 CPU 및 다른 자원을 할당하는 정책을 결정하는 주체
- 목적: 처리량(Throughput) 증대, 응답 시간 단축, 공정성 보장

| 스케줄러 | 역할 | 비고 |
|---|---|---|
| **장기 (Job Scheduler)** | 어떤 프로세스를 메모리(Ready Queue)에 올릴지 결정 | Degree of Multiprogramming 제어. 시분할 시스템에서는 보통 없음 |
| **단기 (CPU Scheduler)** | Ready Queue에서 다음에 Running이 될 프로세스 결정 | 가장 빈번하게 실행 (밀리초 단위) |
| **중기 (Swapper)** | 메모리에 있는 프로세스를 통째로 디스크로 Swap Out | 메모리를 뺏는 문제와 관련 |

- Degree of Multiprogramming(동시에 메모리에 적재된 프로세스 수)이 너무 적으면 CPU 유휴 시간이 길어지고, 너무 많으면 메모리 부족과 과도한 문맥 교환으로 성능이 저하된다.

### Suspended (Stopped)

- 외부적인 이유(사용자 요청, 운영체제의 필요)로 프로세스의 수행이 잠시 정지된 상태
- 통째로 디스크로 Swap Out될 수 있고, Resume 요청 시 다시 Swap In되어 Ready로 돌아감

## 스레드 (Thread, Lightweight Process)

프로세스 내부에서 CPU를 수행하는 여러 개의 실행 단위 → 프로그램 안에서 동시에 여러 작업을 처리

- **스레드별 구성요소**: program counter, register set, stack space
- **공유 부분**: code section, data section, OS resources

![스레드 구조 1](./images/process-4.png)
![스레드 구조 2](./images/process-5.png)

- heavyweight process: 전통적인 개념으로, 프로세스 하나당 스레드 하나를 가지는 태스크
- **스레드의 장점**
  - **응답성**: 하나의 스레드가 대기 상태여도 다른 스레드가 실행되어 응답이 빠르다
  - **처리율 향상**: 여러 스레드가 협력하여 단위 시간당 더 많은 작업을 처리
  - **자원 절약**: 코드, 데이터 섹션 등을 공유하므로 별도 프로세스를 만드는 것보다 자원 소모가 적다
  - **오버헤드 감소**: 스레드 간 문맥 교환은 저장/복원할 정보가 적어 프로세스 문맥 교환보다 가볍다
  - **병렬 처리**: 멀티코어 환경에서 각 스레드가 동시에 실행될 수 있다
