# 운영체제 개요 및 컴퓨터 시스템 구조

## 운영체제 (Operating System, OS)

- 하드웨어 바로 위에 설치되어 소프트웨어와 하드웨어를 연결하는 소프트웨어

### 운영체제의 범위

- **커널 (Kernel)**
  - 운영체제의 핵심
  - 메모리에 상주하면서 컴퓨터 자원 관리
- **넓은 의미**
  - 커널을 포함해 파일 시스템, 사용자 인터페이스, 시스템 유틸리티 등 컴퓨터를 편리하게 사용할 수 있도록 돕는 모든 구성 요소

### 운영체제의 주요 목적

- CPU, 메모리, I/O 장치 등 한정된 컴퓨터 자원들을 최대한 효율적으로 활용하도록 관리
- 여러 사용자가 동시에 컴퓨터를 사용할 때 각 사용자에게 자원이 공정하게 분배되도록 보장
- 하드웨어 동작을 추상화하여 사용자가 컴퓨터를 쉽게 사용할 수 있는 환경(GUI, CLI 등)을 제공 (인터페이스 역할)

### 운영체제의 처리 방식

- **일괄 처리 (Batch Processing)**
  - 작업 요청을 한 번에 모아서 처리하는 방식
  - 모든 작업이 종료될 때까지 기다려야 한다.
- **시분할 (Time Sharing)**
  - CPU 시간을 아주 짧은 단위로 분할하여 여러 작업을 번갈아 가며 처리
  - 동시에 여러 작업을 수행하는 것처럼 보이게 하여 즉각적인 응답을 제공
  - 대부분의 범용 운영체제(Windows, macOS, Linux 등)에 사용
- **실시간 (Real-time)**
  - 정해진 시간 안에 작업이 반드시 종료되는 것을 보장해야 하는 시스템을 위한 OS
  - 산업 제어, 항공 관제, 의료 장비 등 시간 제약이 엄격한 특수 목적 시스템에 사용

## 컴퓨터 시스템 하드웨어 구조

![컴퓨터 시스템 구조](./images/os-overview-1.png)

### CPU

- 명령(Instruction)을 실행하는 장치
- 매 클럭 사이클마다 메모리에서 명령을 읽어 실행
- **레지스터**: CPU 내부의 고속 임시 저장 공간. 명령 실행에 필요한 데이터를 빠르게 접근하고 처리
- **모드 비트**: CPU가 사용자 모드(1)로 동작하는지, 모니터 모드(0, 커널 모드/시스템 모드)로 동작하는지 구분

### 메모리

- CPU의 작업 공간
- CPU가 직접 데이터를 읽고 쓸 수 있다
- 프로그램과 데이터가 저장

### 타이머

- 일정 시간 이후 운영체제에게 제어권이 넘어가도록 인터럽트를 발생시킴
- 타이머 값이 0이 되면 타이머 인터럽트 발생 → CPU 제어권이 운영체제로 넘어감
- 특정 사용자 프로그램이 CPU를 독점하는 것을 방지
- 운영체제가 여러 작업을 번갈아 수행할 수 있도록 함 (시분할)

### DMA (Direct Memory Access) 컨트롤러

- I/O 장치들이 CPU의 개입 없이 직접 메모리에 접근할 수 있도록 돕는 장치
- 원칙적으로는 CPU만 메모리에 직접 접근 가능
- I/O 장치의 로컬 버퍼에 있는 데이터를 CPU를 거치지 않고 메모리로 직접 복사하거나, 반대로 전송
- CPU가 I/O 작업에 직접 관여하지 않아도 되므로 인터럽트 수를 줄여 CPU 성능 저하를 방지

### I/O 장치

**장치 컨트롤러 (Device Controller)**

- 각 I/O 장치의 작업을 통제하는 일종의 작은 CPU
- 제어 레지스터와 상태 레지스터로 구성
- 로컬 버퍼: 장치 컨트롤러 내의 임시 저장 공간 (CPU의 메모리 역할), I/O 장치와 메모리 간 데이터 전송
- I/O 작업이 끝나면 인터럽트를 발생시켜 CPU에게 완료 알림

**장치 구동기 (Device Driver)**

- 운영체제 코드 중 각 장치별 처리 루틴을 담당하는 소프트웨어
- 운영체제가 특정 장치를 제어할 수 있도록 도움

### I/O 방식

- **특권 명령 (Privileged Instruction)**
  - 모든 입출력 명령은 특권 명령
  - 사용자 프로그램이 I/O 장치에 직접 접근하거나 명령을 내릴 수 없음
- **시스템 콜 (System Call)**
  - 사용자 프로그램이 I/O 같은 운영체제의 서비스를 받기 위해 요청하는 것
  - 트랩(Trap)이라는 소프트웨어 인터럽트를 사용
    → 인터럽트 벡터의 특정 위치로 이동
    → 인터럽트 서비스 루틴(ISR)으로 제어권을 넘김
  - 올바른 요청인지 확인 후 작업을 수행
    → 완료 후 시스템 콜 다음 명령어로 제어권을 사용자 프로그램에 돌려줌

## 인터럽트 (Interrupt)

- 현재 실행 중인 작업을 잠시 중단시키고 다른 긴급한 작업을 처리하도록 하는 신호

### 인터럽트의 종류

- **인터럽트**: 하드웨어가 발생시키는 신호
- **트랩**: 소프트웨어가 발생시키는 인터럽트
  - 예외 (Exception): 프로그램 실행 중 오류가 발생한 경우
  - 시스템 콜

### 인터럽트 처리 과정

1. 하드웨어 또는 소프트웨어로부터 인터럽트 신호 발생
2. CPU가 현재 실행 중이던 작업을 즉시 중단
3. 중단된 작업의 현재 상태(컨텍스트: CPU 레지스터 값, 프로그램 카운터 등)를 메모리에 저장
4. 발생한 인터럽트의 종류를 식별
5. 인터럽트 벡터 테이블에서 해당 ISR의 시작 주소를 찾음
6. ISR(커널 함수) 실행
7. ISR 실행 완료 후 저장했던 컨텍스트를 복원
8. 중단되었던 작업을 이어서 실행
