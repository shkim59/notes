# 프록시

- 중개자: 클라이언트와 서버 사이에 위치해 트랜잭션을 수행하는 중개인
- **개인 프록시**: 클라이언트 컴퓨터에서 직접 실행
- **공유 프록시**: 대부분의 프록시, 중앙 집중형

## 프록시 vs 게이트웨이

| | 프록시 | 게이트웨이 |
|---|---|---|
| 연결 대상 | 같은 프로토콜을 사용하는 둘 이상의 애플리케이션 | 서로 다른 프로토콜을 사용하는 둘 이상의 애플리케이션 |
| 비고 | SSL 보안 프로토콜, SOCKS 방화벽, FTP 접근 등 게이트웨이 기능을 구현하기도 함 | 프로토콜 변환기처럼 동작 |

- 보안 개선, 성능 향상, 비용 절감
- 모든 HTTP 트래픽을 보고 수정할 수 있다
- 부가적인 가치를 주는 웹 서비스를 구현하기 위해 트래픽을 감시, 수정할 수 있다.

## 프록시 서버 배치

- 출구 프록시
- 접근 프록시 (캐시 프록시, ISP)
- 대리 프록시
  - 웹 서버 앞에 위치
  - 웹 서버로 보내는 요청을 처리하고 필요할 때만 웹 서버에 자원을 요청
  - 보안 기능 추가, 캐시를 이용한 성능 개선
- 네트워크 교환 프록시

## 프록시 계층

- 부모: 서버에 가까운 쪽

## 트래픽 처리

- **클라이언트**: 대부분의 브라우저가 자동 프록시 설정을 지원. 설정되어 있다면 HTTP 요청을 의도적으로 프록시로 보냄
- **네트워크**: 네트워크 인프라를 가로채서 트래픽이 프록시로 가도록 조정 (스위칭·라우팅 장치 필요, 인터셉트 프록시)
- **DNS**
- **웹 서버**: 리다이렉션 명령으로 요청을 프록시로 리다이렉트하도록 설정할 수 있다

## 클라이언트 프록시 설정

- PAC (프록시 자동 설정) 파일
- WPAD (웹 프록시 자동 발견): 브라우저에게 알맞은 PAC 파일을 자동으로 찾아주는 알고리즘. 성공할 때까지 다음 기법들을 하나씩 시도
  - 동적 호스트 발견 규약 (DHCP)
  - 서비스 위치 규약 (SLP)
  - DNS 잘 알려진 호스트명
  - DNS SRV 레코드
  - DNS TXT 레코드 안의 서비스 URI

## 프록시 요청의 특징

프록시 URI는 서버 URI와 다르다.

- **클라이언트 → 서버: 부분 URI** (`GET /index.html HTTP/1.0`)
  - 단일 서버는 자신의 호스트명과 포트번호를 알고 있으므로, 불필요한 정보 발송을 피하기 위해 스킴과 호스트가 없는 부분 URI만 보냄
- **클라이언트 → 프록시: 전체 URI** (`GET http://www.example.com/...`)
  - 목적지 서버와 커넥션을 맺어야 하기 때문에 서버의 이름을 알아야 함
  - 다른 스킴과 연결하기 위해 URI의 스킴을 알아야 함

## 메시지 추적

- `Via` 헤더: 메시지가 지나는 중간 노드를 기록
- `TRACE` 메서드: 프록시 흐름을 디버깅하는 데 유용하다
