# JVM & JIT 컴파일러

## 인터프리터 vs 컴파일러

- **인터프리터**: 코드를 한 줄씩 읽어서 즉시 번역하고 실행
  - **장점**: 전체 코드를 미리 번역할 필요 없이 즉시 실행 → 시작 속도가 빠름
  - **단점**
    - 매번 번역 과정을 거침 → 같은 코드가 반복될 때 비효율적
    - 전체 실행 속도가 느림
- **컴파일러**: 코드를 전체적으로 미리 읽어 한 번에 네이티브 코드(기계어)로 변환
  - **장점**: 번역 과정 없이 네이티브 코드를 바로 실행하므로 실행 속도가 매우 빠름
  - **단점**: 전체 코드를 번역하는 데 시간이 걸림 → 초기 시작이 느림

### 자바는?

- **1차 컴파일 (javac): 소스 코드(.java) → 바이트코드(.class)**
  - 바이트코드는 JVM이 이해할 수 있는 중간 언어
  - CPU가 직접 이해하고 실행할 수는 없음
- **JVM 런타임에서의 변환: 바이트코드(.class) → 네이티브 코드**
  - `java` 명령어로 .class 파일을 실행하면 JVM이 바이트코드를 네이티브 코드로 변환하여 실행

## HotSpot JVM

- **인터프리터**
  - 처음에는 바이트코드를 한 줄씩 읽어서 네이티브 코드로 변환하고 실행
  - 컴파일하지 않아 빠르게 시작됨
- **JIT 컴파일러**
  - 코드를 실행하면서 자주 사용되는 코드(Hot Spot)를 프로파일링
  - 특정 코드가 핫 스팟으로 감지되면 해당 바이트코드를 네이티브 코드로 컴파일
  - 네이티브 코드는 메모리에 캐싱되고, 이후 동일한 코드가 실행될 때 즉시 실행

## JIT (Just-In-Time) 컴파일러

### C1 컴파일러 (Client Compiler)

- **목표**: 빠른 시작 속도와 응답성
- **특징**
  - 컴파일 속도가 매우 빠름
  - 기본적인 최적화만 수행 (메서드 인라이닝, 간단한 루프 최적화)
  - 데스크톱 애플리케이션이나 실행 시간이 짧은 프로그램에 적합
- **역할**
  - 계층적 컴파일의 초기 단계
  - 호출 횟수 임계점을 넘은 코드를 네이티브 코드로 컴파일해 1차적인 성능 향상 제공
  - C2 컴파일러가 사용할 프로파일링 데이터를 수집

### C2 컴파일러 (Server Compiler)

- **목표**: 높은 성능 (Peak Performance)
- **특징**
  - C1 단계에서 수집된 프로파일링 데이터를 기반으로 코드 동작을 분석
  - C1보다 느리지만 정교한 최적화 수행
    - 공격적 메서드 인라이닝: 더 많은 메서드를 호출 지점에 직접 삽입해 오버헤드 제거
    - 루프 언롤링: 루프를 풀어써서 분기 예측 실패를 줄이고 실행 속도를 높임
    - 탈출 분석(Escape Analysis): 메서드 외부로 탈출하지 않는 객체를 스택에 할당하거나 락을 제거
  - 오랜 시간 중단 없이 실행되는 서버 애플리케이션에 최적화
- **역할**: 계층적 컴파일의 최종 단계. C1이 컴파일한 코드 중 핵심 코드를 더 높은 수준으로 최적화

## 계층적 컴파일 (Tiered Compilation)

**도입 전**: `-client` 또는 `-server` 옵션으로 JIT 컴파일러를 직접 선택

| 옵션 | 목표 | 적합 | 한계 |
|---|---|---|---|
| `-client` (C1) | 빠른 시작, 낮은 메모리 | 데스크톱, 짧게 실행되는 프로그램 | 장기적인 피크 성능 낮음 |
| `-server` (C2) | 장시간 실행 시 최고 성능 | 서버 애플리케이션 | 시작이 느림 |

**도입 후**

- **Level 0 (인터프리터)**: 바이트코드를 한 줄씩 해석하며 실행, 기본 프로파일링 정보 수집 → 빠른 초기 시작 담당
- **Level 1, 2, 3 (C1)**: 호출 임계값을 넘은 코드를 빠르게 컴파일. 레벨별로 프로파일링 수집 정도와 최적화 강도가 다름
- **Level 4 (C2)**: 실행 빈도가 매우 높은 핵심 코드를 C1의 프로파일링 데이터 기반으로 재컴파일해 피크 성능 달성

## GraalVM

Oracle에서 개발한 고성능 JDK 배포판

- **Graal JIT 컴파일러**
  - 자바로 작성됨 (기존 HotSpot의 C1/C2는 C++)
  - 모듈화, 유지보수성, 확장성 향상
- **AOT 컴파일 (Native Image)**
  - 바이트코드를 실행 전에 특정 OS/아키텍처용 네이티브 실행 파일로 미리 컴파일
  - JVM 없이 단독 실행 가능
  - JIT 워밍업이 없어 시작 속도가 매우 빠르고 메모리 사용량이 낮음 → 마이크로서비스, 서버리스에 유리
  - 런타임 프로파일링 데이터를 쓸 수 없어 장시간 실행 시 피크 성능은 JIT보다 약간 낮을 수 있음
- **다중 언어 지원 (Polyglot) 및 Truffle 프레임워크**
  - JavaScript, Python, Ruby, R, WebAssembly, C/C++ 등을 하나의 런타임에서 실행하고 상호 운용
