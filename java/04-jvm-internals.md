# JVM 동작 원리

## JVM (Java Virtual Machine)

- 자바 코드가 실행되는 런타임 환경을 제공하는 가상 머신
- 특정 하드웨어 플랫폼에 종속되지 않고 자바 코드 실행 환경을 제공
- Write Once, Run Anywhere

## 주요 동작 원리

### 1. 자바 소스 코드 컴파일

- `javac` 컴파일러가 자바 소스 코드(.java)를 바이트코드(.class)로 컴파일
- 바이트코드는 JVM이 이해할 수 있는 중간 언어 (특정 OS나 하드웨어에 종속되지 않음)

### 2. 클래스 로더 시스템

- JVM이 시작되거나 실행 중 새로운 클래스가 필요할 때 `.class` 파일을 로드해 런타임 데이터 영역으로 가져옴
- 단계
  - **로딩 (Loading)**: `.class` 파일을 읽어 JVM 메모리에 저장하고 해당 클래스의 `Class` 객체 생성
  - **링크 (Linking)**
    - **검증 (Verification)**: 유효한 바이트코드인지, 보안상 문제가 없는지 확인
    - **준비 (Preparation)**: static 변수에 메모리를 할당하고 기본값으로 초기화
    - **해결 (Resolution)**: 심볼릭 레퍼런스를 직접 레퍼런스로 변환
  - **초기화 (Initialization)**: static 필드에 값을 할당하고 static 블록 실행

### 3. 런타임 데이터 영역

| 영역 | 공유 여부 | 저장 내용 |
|---|---|---|
| 메서드 영역 | JVM당 1개, 모든 스레드 공유 | 클래스 정보, 정적 변수, 상수 풀 |
| 힙 영역 | JVM당 1개, 모든 스레드 공유 | 인스턴스(객체), 배열 → GC 대상 |
| 스택 영역 | 스레드마다 | 스택 프레임(지역 변수, 매개변수, 리턴 주소) |
| PC 레지스터 | 스레드마다 | 현재 실행할 JVM 명령어 주소 |
| 네이티브 메서드 스택 | 스레드마다 | C/C++ 등 네이티브 메서드 호출용 스택 |

### 4. 실행 엔진

- **인터프리터**: 바이트코드를 한 줄씩 읽어서 실행. 느리지만 초기 구동이 빠름
- **JIT 컴파일러**: 반복 실행되는 코드(핫 스팟)를 기계어로 컴파일하고 캐싱 → 이후 바로 실행
- **가비지 컬렉터**: 힙에서 더 이상 참조되지 않는 객체를 찾아 제거하고 메모리를 회수

### 5. JNI (Java Native Interface)

- 자바 코드가 C, C++ 등으로 작성된 네이티브 라이브러리나 OS 기능을 호출할 수 있게 해주는 인터페이스

### 6. 네이티브 메서드 라이브러리

- JNI를 통해 호출되는 라이브러리. 운영체제나 하드웨어에 특화된 기능 제공
