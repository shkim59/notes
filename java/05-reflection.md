# 리플렉션 (Reflection)

## 개념

- 프로그램 실행 중에 자신의 구조(클래스, 메서드, 필드 등)를 검사하고 조작할 수 있는 기능
- 컴파일 시점이 아닌 런타임에 클래스의 정보를 알아내거나, 객체를 생성하고, 메서드를 호출하거나, 필드 값을 변경하는 작업을 동적으로 수행
- 일반적으로 자바 프로그램은 컴파일 시점에 클래스나 메서드에 대한 정보가 결정되지만, 리플렉션은 이 제약을 벗어나 런타임에 코드 자체를 데이터처럼 다룰 수 있게 해줌

## 장점

- **동적인 객체 생성 및 메서드 호출**: 설정 파일이나 DB에서 클래스 이름을 읽어와 객체를 생성하고 메서드를 호출할 수 있다. 플러그인 아키텍처나 프레임워크 개발에 필수적
- **유연한 코드 작성**: 특정 인터페이스를 구현하는 다양한 클래스를 동적으로 처리. 제네릭, 애노테이션 처리와 결합해 확장성 있는 코드 작성
- **디버깅 및 테스트 도구**: 런타임에 객체의 내부 상태를 확인하거나 private 멤버에 접근. Mock 객체 생성, 테스트 프레임워크에 활용
- **프레임워크 개발**: Spring, Hibernate 등이 DI, AOP, ORM 같은 핵심 기능을 리플렉션으로 구현

## 단점

- **성능 저하**: 런타임에 클래스 정보를 탐색하고 접근 권한을 확인하는 추가 작업 → 성능에 민감한 부분에서는 지양
- **보안 취약성**: private 멤버 접근, final 필드 변경 등 접근 제어를 무시할 수 있음
- **유지보수 어려움**: 과도하게 사용하면 코드를 이해하고 추적하기 어려움
- **컴파일 타임 에러 검출 불가**: 메서드 이름 오타, 없는 필드 접근 등을 런타임에야 발견
- **버전 제약**: Java 9 모듈 시스템(JPMS) 도입으로 리플렉션을 통한 접근이 더 엄격해짐

## Class 객체 얻기

`java.lang.reflect` 패키지의 `Class`, `Method`, `Field` 객체가 핵심. `Class` 객체는 클래스의 메타데이터(이름, 필드, 메서드, 생성자 등)를 나타낸다.

- `Class.forName("클래스_풀네임")`: 클래스 이름 문자열로 로드 (외부에서 클래스 이름을 받아올 때)
- `객체.getClass()`: 이미 생성된 객체로부터 얻기
- `클래스명.class`: 컴파일 시점에 알려진 클래스에 대해 얻기
