## 데이터 종류

| 종류 | 예 | 특징 | 저장 위치 |
|---|---|---|---|
| **애플리케이션** | 소스 코드, 환경 | 빌드 후 바뀌면 안 됨. 바꾸려면 이미지 재빌드 | **이미지** (읽기 전용) |
| **임시 데이터** | 실행 중 입력값, 메모리 변수 | 읽기/쓰기, 컨테이너가 사라지면 없어져도 됨 | **컨테이너 레이어** (이미지 위에 도커가 추가한 읽기/쓰기 계층) |
| **영구 데이터** | 사용자 계정, 업로드 파일, DB 데이터 | 읽기/쓰기, 컨테이너가 사라져도 유지되어야 함 | **볼륨** |

## 볼륨

호스트 머신의 폴더를 컨테이너 내부 경로와 매핑하는 것. 컨테이너가 삭제되어도 데이터를 유지할 수 있다.

- Dockerfile의 `VOLUME` 명령어 또는 실행 시 `-v` 옵션으로 설정한다.

| 종류 | 명령 | 수명 | 용도 |
|---|---|---|---|
| **익명 볼륨** | `-v /app/data` | 컨테이너에 종속. `--rm`으로 실행한 컨테이너가 삭제되면 함께 삭제 | 컨테이너 안의 특정 경로를 바인드 마운트에서 덮어쓰지 않게 보호 (예: `node_modules`) |
| **Named 볼륨** | `-v VOLUME_NAME:/app/data` | 컨테이너가 삭제되어도 유지 | 영구 데이터 (호스트에서 직접 편집할 필요는 없는 것) |
| **바인드 마운트** | `-v /host/path:/app/data` | 호스트 폴더 그 자체 | 소스 코드처럼 **호스트에서 편집하고 즉시 반영**해야 하는 데이터 |

```bash
docker run -v /app/data IMAGE                 # 익명 볼륨
docker run -v feedback:/app/data IMAGE        # named 볼륨
docker run -v "$(pwd)":/app IMAGE             # 바인드 마운트
```

> 도커가 관리하는 익명·named 볼륨은 호스트의 어디에 저장되는지 알 필요가 없다. 바인드 마운트는 경로를 직접 지정한다.
