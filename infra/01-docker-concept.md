## 도커

애플리케이션을 **컨테이너 단위로 패키징**해서 관리하는 오픈 소스 플랫폼. 개발 환경과 운영 환경의 불일치를 줄이고 배포·확장·관리를 쉽게 한다.

### 컨테이너

코드와, 그 코드를 실행하는 데 필요한 종속성·도구를 함께 묶은 표준화된 소프트웨어 유닛. 같은 코드와 같은 종속성으로 어디서나 같은 결과를 낸다.

| 특징 | 설명 |
|---|---|
| 독립성 | 애플리케이션이 격리되어 다른 컨테이너와 환경·데이터가 충돌하지 않음 |
| 이식성 | 도커가 설치된 곳이면 어디서든 같은 환경으로 실행 |
| 일관성 | 개발·테스트·운영에서 항상 같은 실행 환경 |
| 경량화 | VM과 달리 OS 커널을 공유해 적은 리소스로 많은 애플리케이션 실행 |

### 왜 쓰나

1. **개발·배포 환경 일치**: 로컬은 Node 14.3인데 서버는 구버전인 식의 불일치를 없앤다.
2. **팀 협업**: 팀원마다 버전이 달라 같은 코드가 다르게 동작하는 문제를 막는다.
3. **프로젝트 간 버전 충돌 방지**: Python 2 프로젝트와 최신 Python 프로젝트를 각자의 컨테이너로 유지한다.
4. **재현성**: 같은 코드가 항상 같은 결과를 내므로 배포 전 테스트 환경을 그대로 맞출 수 있다.

## 핵심 개념

| 개념 | 설명 |
|---|---|
| **이미지** | 컨테이너의 템플릿. 애플리케이션과 라이브러리, 설정이 포함된 **불변(읽기 전용)** 파일 시스템 스냅샷 |
| **컨테이너** | 이미지를 기반으로 실행되는 격리된 인스턴스. 리눅스 커널의 가상화 기능으로 다른 프로세스와 격리됨 |
| **Dockerfile** | 이미지 생성을 자동화하는 설정 파일. 빌드와 설정을 정의 → [Dockerfile 명령어](./02-dockerfile.md) |

### 이미지

- 공유 가능한 패키지로, 같은 이미지로 여러 컨테이너를 시작할 수 있다.
- 애플리케이션과 실행 환경(OS, 런타임, 코드, 도구)에 필요한 모든 설정 명령이 들어 있다.
- Docker Hub의 공식 이미지처럼 미리 빌드된 것을 쓰거나 Dockerfile로 직접 빌드한다.
- 한 번 빌드되면 **읽기 전용**으로 잠긴다. 바꾸려면 Dockerfile을 수정해 새 이미지를 만들어야 한다.
- 이미지 자체는 실행되지 않고, 컨테이너로 실행된다.

### 컨테이너

- 이미지의 구체적인 실행 인스턴스. `docker run`으로 생성·실행한다.
- 로컬에 이미지가 없으면 Docker Hub에서 자동으로 가져온다.
- 개발과 프로덕션에서 실제로 실행되는 것은 결국 컨테이너다.

## 레이어 아키텍처

![이미지 레이어 구조](./images/docker-layers.png)

- **불변**: 각 레이어는 변경되지 않고, 변경 사항은 새 레이어를 쌓는 방식으로 반영된다.
- **계층 구조**: 각 레이어는 이전 레이어를 참조하고, 이미지는 레이어들의 합이다.
- **독립성**: 각 레이어는 독립적으로 관리·저장된다.
- 컨테이너를 실행하면 이미지 위에 **읽기/쓰기 가능한 컨테이너 레이어**가 하나 더 추가된다.

## 캐싱 메커니즘

- Dockerfile의 각 명령어(`RUN`, `COPY`, `ADD` 등)는 새 레이어를 만들고 캐시로 저장된다.
- 명령어와 그 입력이 바뀌지 않았으면 캐시된 레이어를 재사용한다.
- **어떤 단계에서 변경이 생기면, 그 이전 레이어는 캐시를 쓰지만 이후의 모든 레이어는 새로 만든다.** 변경 사항이 이미지에 올바르게 반영되도록 하기 위함이다.

### 캐시를 고려한 Dockerfile

```dockerfile
# ❌ 소스 한 줄만 바뀌어도 npm install이 다시 실행됨
FROM node:14
WORKDIR /app
COPY . .
RUN npm install
EXPOSE 3000
CMD ["node", "app.mjs"]
```

```dockerfile
# ✅ package.json이 그대로면 npm install은 캐시 사용
FROM node:14
WORKDIR /app
COPY package.json .
RUN npm install
COPY . .
EXPOSE 3000
CMD ["node", "app.mjs"]
```

1. `COPY package.json .` — 라이브러리를 새로 추가하지 않으면 잘 안 바뀌어서 캐시가 자주 쓰인다.
2. `RUN npm install` — `package.json`이 그대로면 캐시를 쓴다.
3. `COPY . .` — 소스가 바뀌어도 앞 단계는 캐시를 쓴다.

→ 소스가 자주 바뀌는 개발 환경에서 빌드 시간이 크게 줄어든다. **자주 바뀌는 것일수록 아래쪽에** 둔다.
