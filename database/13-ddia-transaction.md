# 트랜잭션

> 『데이터 중심 애플리케이션 설계』 7장 정리

- 애플리케이션에서 여러 읽기와 쓰기를 **하나의 논리적 단위**로 묶는 방법
- 한 트랜잭션 안의 모든 읽기와 쓰기는 하나의 연산처럼 실행되어, **전체가 성공(commit)하거나 전체가 실패(abort)**한다
- 목적: 프로그래밍 모델을 단순화하는 것

## 복잡성의 은폐

- 현실의 시스템은 언제든 실패할 수 있다 (DB 소프트웨어가 죽거나, 네트워크가 끊기거나, 디스크가 꽉 차거나, 여러 클라이언트가 동시에 쓰거나)
- 트랜잭션은 이런 문제를 **전부 성공하거나, 아예 없었던 일로 만드는** 하나의 단위로 묶는다
- 개발자는 부분 실패(partial failure)에 대한 복잡한 예외 처리를 신경 쓰지 않아도 된다

## ACID

### 원자성 (Atomicity)

- 더 이상 쪼갤 수 없는 단위. 트랜잭션 안의 쓰기 중 하나라도 실패하면 전체가 취소(rollback)
- 원자성은 **동시성과는 관련이 없다** (그건 격리성의 영역)

### 일관성 (Consistency)

- 데이터는 항상 불변식(invariant)을 만족해야 한다
- 데이터베이스만으로는 보장되지 않고, **애플리케이션의 책임**에 가까운 속성

### 격리성 (Isolation)

- 같은 레코드에 동시에 접근하면 동시성 문제가 생긴다
- 동시에 실행되는 트랜잭션은 서로 격리되어 방해할 수 없어야 한다
- 이상적으로는 트랜잭션을 순차적으로 실행한 것과 같은 결과를 내야 한다 (직렬성)

### 지속성 (Durability)

- 성공적으로 커밋된 트랜잭션의 데이터는, 하드웨어 결함이 생기거나 DB가 죽어도 손실되지 않는다는 보장
