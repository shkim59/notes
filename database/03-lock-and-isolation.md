# 잠금과 트랜잭션 격리 수준

## 잠금

### MySQL 엔진 레벨

- **글로벌 락**
  - 데이터베이스 서버 전체에 대한 잠금
  - 데이터베이스 백업 작업 등
- **테이블 락**
  - 테이블에 대한 잠금
  - 테이블 구조 변경 (DDL)
- **네임드 락**
  - 사용자가 지정한 문자열에 대한 잠금
  - 여러 서버에 분산된 애플리케이션 간의 동기화
- **메타데이터 락**
  - 데이터베이스 객체(테이블, 뷰)의 이름이나 구조를 변경하는 경우 획득

### InnoDB 엔진 레벨

- **레코드 락**
  - 인덱스 레코드에 대한 잠금
  - 인덱스가 없는 경우 자동 생성된 클러스터 인덱스를 이용
- **갭 락**
  - 레코드와 인접한 레코드 사이의 간격을 잠금
  - 레코드 사이 간격에 새로운 레코드가 생성되는 것을 제어
- **넥스트 키 락**
  - 레코드 락과 갭 락의 조합
  - 레코드와 레코드 앞의 갭을 함께 잠금
- **자동 증가 락**
  - `AUTO_INCREMENT`에 대한 잠금
  - 트랜잭션과 관계없이 `AUTO_INCREMENT` 값을 가져오는 순간 락이 걸렸다가 해제된다.

### 인덱스 기반

- 레코드를 찾기 위해 검색한 인덱스의 모든 레코드에 대해 잠금 설정
- 인덱스가 없으면 모든 레코드에 대해 잠금 설정

## 격리 수준

### READ UNCOMMITTED

- 데이터 정합성 문제로 사용 X
- Dirty Read: 다른 트랜잭션이 커밋하지 않은 변경 사항을 읽는 것

![Dirty Read](./images/isolation-1.png)

### READ COMMITTED

- 오라클의 기본 격리 수준
- 언두 로그에 백업된 데이터를 조회

![READ COMMITTED](./images/isolation-2.png)

- NON-REPEATABLE READ 부정합 문제가 발생할 수 있다.
  - 트랜잭션 내에서 쿼리문의 조회 결과가 변경되는 것

![NON-REPEATABLE READ](./images/isolation-3.png)

### REPEATABLE READ

- InnoDB 스토리지 엔진의 기본 격리 수준
- NON-REPEATABLE READ 문제 해결
- 언두 로그에서 트랜잭션 아이디가 해당 트랜잭션 아이디보다 작은 데이터 조회

![REPEATABLE READ](./images/isolation-4.png)

- PHANTOM READ 현상 발생 → 갭 락과 넥스트 키 락으로 방지

![PHANTOM READ](./images/isolation-5.png)

### SERIALIZABLE

- 가장 엄격한 격리 수준
- PHANTOM READ 문제가 발생하지 않는다.

## 부록: 잠금 상세 정리

### 글로벌 락

- 범위가 가장 큰 잠금
- 한 세션에서 글로벌 락을 획득하면 다른 모든 세션의 데이터 변경 작업이 대기 상태로 전환 (읽기 작업은 계속 가능)
- 데이터베이스의 모든 테이블에 영향을 미침
- 용도: 전체 MySQL 서버의 상태를 일관되게 유지해야 하는 백업 작업, 여러 데이터베이스에 걸친 일관된 스냅샷 생성
- 예시: 밤 12시에 전체 데이터베이스 백업을 진행할 때, 백업 도중 데이터가 변경되면 일관성이 깨질 수 있으므로 글로벌 락을 사용

### 테이블 락

특정 테이블 전체에 적용되는 잠금

- **획득 방법**
  - 명시적: `LOCK TABLES 테이블명 READ/WRITE`
  - 자동: 테이블 구조 변경(`ALTER TABLE`) 등의 DDL 문 실행 시
- **특징**
  - READ 락: 여러 세션이 동시에 읽기 가능, 쓰기는 불가
  - WRITE 락: 획득한 세션만 읽기와 쓰기 가능, 다른 세션들은 접근 불가
  - 명시적 테이블 락은 `UNLOCK TABLES`로 해제하거나 세션 종료 시 자동 해제
- **주요 용도**: MyISAM 같은 스토리지 엔진에서 주로 사용, 테이블 구조 변경 작업 시
- 예시: 제품 카탈로그 테이블을 전면 개편하는 작업을 할 때 테이블 락을 걸어 데이터 일관성 유지

### 네임드 락

사용자가 지정한 문자열(이름)에 대한 잠금

- **획득 방법**: `GET_LOCK('락이름', 타임아웃)`으로 획득, `RELEASE_LOCK('락이름')`으로 해제
- **특징**
  - 데이터베이스 객체가 아닌 사용자 정의 문자열에 대한 잠금
  - 한 번에 하나의 세션만 특정 이름의 락을 획득 가능
  - 세션이 종료되거나 연결이 끊기면 자동으로 해제
- **주요 용도**: 여러 서버에 분산된 애플리케이션 간의 동기화, 특정 코드 블록이 한 번에 하나씩만 실행되도록 보장
- 예시: 여러 웹 서버가 동시에 일일 배치 작업을 실행하지 않도록 `daily_batch` 이름의 락을 사용해 하나의 서버만 실행하도록 제어

### 메타데이터 락

데이터베이스 객체의 구조를 보호하는 잠금

- **획득 방법**: DDL(CREATE, ALTER, DROP) 및 DML(SELECT, INSERT, UPDATE) 문 실행 시 자동으로 획득
- **특징**
  - 테이블의 구조 정보(메타데이터)를 보호
  - 테이블 스키마 변경 중에는 해당 테이블의 모든 읽기/쓰기 작업이 대기
  - 트랜잭션 내에서 테이블 접근 시, 트랜잭션이 완료될 때까지 메타데이터 락 유지
- 예시: 사용자 A가 조회하는 긴 트랜잭션을 시작했는데 사용자 B가 같은 테이블의 구조를 변경하려고 하면, A의 트랜잭션이 끝날 때까지 구조 변경이 대기

### 레코드 락

- **대상**: 인덱스 레코드 자체
- 행 단위로 잠금이 걸려 동시성이 높음, 다른 트랜잭션의 해당 레코드 변경을 차단
- **획득 방법**: `SELECT ... FOR UPDATE` (배타 잠금), `SELECT ... FOR SHARE` (공유 잠금)
- 예시: 송금 거래에서 특정 계좌의 잔액을 갱신할 때 해당 계좌 레코드만 잠금

### 갭 락

- **대상**: 인덱스 레코드 사이의 범위
- 존재하지 않는 레코드의 삽입을 방지 → 팬텀 읽기 방지, REPEATABLE READ에서 작동
- **획득 방법**: `SELECT ... FOR UPDATE` 같은 잠금 읽기 시 자동 획득
- 예시: ID 값이 10~20 사이인 데이터를 조회하는 트랜잭션에서 해당 범위에 새로운 데이터가 삽입되는 것을 방지

### 넥스트 키 락

- **대상**: 인덱스 레코드와 그 직전의 갭
- InnoDB의 기본 잠금 방식 (REPEATABLE READ)
- 레코드 변경 방지와 팬텀 읽기 방지를 동시에 수행
- 예시: 가격이 1000원 이상인 상품을 조회하는 트랜잭션에서 조회 결과에 영향을 줄 수 있는 모든 삽입과 수정을 방지

### 자동 증가 락

- **대상**: `AUTO_INCREMENT` 값을 생성하는 메커니즘
- 매우 짧은 시간 동안만 유지되는 테이블 수준의 잠금, INSERT 문이 완료되면 즉시 해제
- `innodb_autoinc_lock_mode`로 동작 방식 조정
  - 0: 전통적 방식 (삽입 완료까지 잠금)
  - 1: 연속 모드 (대부분 상황에서 최적화)
  - 2: 인터리빙 모드 (가장 빠르지만 복제 환경에서 주의 필요)

### 인덱스와 잠금

1. **인덱스 기반 잠금**: InnoDB는 레코드가 아니라 인덱스 엔트리를 잠근다. 인덱스가 없는 테이블도 내부적으로 숨겨진 클러스터 인덱스가 생성된다.
2. **인덱스 선택과 잠금 범위**: WHERE 조건에 사용된 인덱스에 따라 잠금 범위가 결정된다. 인덱스를 쓰지 못하면 풀 스캔이 발생해 과도한 잠금이 걸릴 수 있다.
3. **보조 인덱스 사용 시**: 보조 인덱스 레코드를 먼저 잠그고, 그 PK로 클러스터 인덱스 레코드도 잠근다 (두 단계 잠금).
4. **인덱스 없는 조건 검색**: `WHERE name = '홍길동'`에서 name에 인덱스가 없으면 테이블의 모든 레코드가 잠긴다.
5. **커버링 인덱스**: 클러스터드 인덱스에 대한 추가 잠금이 필요 없어 잠금 경합이 줄어든다.
6. **복합 인덱스**: (col1, col2) 인덱스에서 col1만 조건으로 쓰면 col2 값과 관계없이 col1 조건에 맞는 모든 레코드가 잠긴다.
7. **인덱스 레인지 스캔**: 범위에 해당하는 레코드와 갭에 넥스트 키 락이 걸려 단일 레코드 검색보다 더 많이 잠길 수 있다.
8. **잠금 정보 확인**: `SHOW ENGINE INNODB STATUS`, `performance_schema` 테이블

### 트랜잭션과 격리 수준

- 트랜잭션: 데이터의 정합성을 보장하기 위한 기능. 작업이 모두 적용되거나 모두 적용되지 않는 것을 보장
- 격리 수준: 여러 트랜잭션이 동시에 처리될 때, 특정 트랜잭션이 다른 트랜잭션에서 변경하거나 조회하는 데이터를 볼 수 있게 허용할지를 결정하는 것
