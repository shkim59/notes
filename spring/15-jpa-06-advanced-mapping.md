# JPA 6. 고급 매핑

## 상속관계 매핑

- 객체에는 상속이 있지만 관계형 DB에는 없다
- DB의 **슈퍼타입-서브타입 관계** 모델링이 그나마 상속과 유사하다
- 상속관계 매핑 = 객체의 상속 구조와 DB의 슈퍼타입-서브타입 관계를 매핑하는 것

<!-- ![상속관계](./images/jpa06-1.png) -->

### 주요 어노테이션

- `@Inheritance(strategy = InheritanceType.XXX)`
  - `JOINED`: 조인 전략
  - `SINGLE_TABLE`: 단일 테이블 전략 (기본값)
  - `TABLE_PER_CLASS`: 구현 클래스마다 테이블 전략
- `@DiscriminatorColumn(name = "DTYPE")`: 부모 클래스에 선언. 하위 클래스를 구분하는 컬럼
- `@DiscriminatorValue("XXX")`: 하위 클래스에 선언. 구분 컬럼에 저장할 값

### 조인 전략

<!-- ![조인 전략](./images/jpa06-2.png) -->

- 엔티티 각각을 테이블로 만들고, 자식 테이블이 부모의 기본 키를 **기본 키 + 외래 키**로 사용
- 자식 테이블의 PK 컬럼명을 바꾸려면 `@PrimaryKeyJoinColumn(name = "BOOK_ID")`
- **장점**: 테이블 정규화, 외래 키 참조 무결성 활용, 저장 공간 효율적 (불필요한 null 없음)
- **단점**: 조회 시 조인이 많아 성능 저하, 쿼리 복잡, 저장 시 INSERT 2번

### 단일 테이블 전략

<!-- ![단일 테이블 전략](./images/jpa06-3.png) -->

- 한 테이블에 모두 저장하고 `DTYPE`으로 구분. 서브타입이 쓰지 않는 컬럼은 null
- **장점**: 조인이 없어 조회가 빠르고 쿼리가 단순
- **단점**: 자식 엔티티의 컬럼은 모두 null을 허용해야 함, 테이블이 커지면 오히려 느려질 수 있음

### 구현 클래스마다 테이블 전략 (사용 X)

<!-- ![구현 클래스마다 테이블](./images/jpa06-4.png) -->

- **장점**: 서브타입을 명확히 구분할 때 효과적, not null 제약 사용 가능
- **단점**: 여러 자식을 함께 조회하면 UNION이 필요해 느림, 통합 쿼리가 어려움

> 💡 **전략 선택**
> - 기능이 단순하고 확장 가능성이 적으면 **단일 테이블 전략**
> - 비즈니스적으로 중요하고 복잡하며 확장 가능성이 높으면 **조인 전략**

## @MappedSuperclass - 매핑 정보 상속

<!-- ![MappedSuperclass](./images/jpa06-5.png) -->

- 객체 입장에서 **공통 매핑 정보**가 필요할 때 사용 (등록일, 수정일, 등록자, 수정자 등)
- 엔티티가 아니고 테이블과 매핑되지 않는다. 자식 클래스에 **매핑 정보만 제공**
- 부모 타입으로 조회·검색 불가 (`em.find(BaseEntity)` 불가)
- 직접 생성할 일이 없으므로 **추상 클래스 권장**

> 참고: `@Entity` 클래스는 엔티티나 `@MappedSuperclass`로 지정한 클래스만 상속할 수 있다
