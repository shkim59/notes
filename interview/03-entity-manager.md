# 엔티티 매니저에 대해 설명해주세요

> 출처: 매일메일(maeil-mail) 면접 질문. 원문을 옮겨 적은 노트라 외부 공개 시에는 직접 다시 정리할 것.

- **영속성 컨텍스트**: 엔티티를 영구 저장하는 환경. 1차 캐시, 쓰기 지연, 변경 감지로 영속 로직을 효율적으로 처리한다.
- 이를 위해 엔티티는 영속성 컨텍스트에서 관리되어야 하고, 그 작업을 돕는 것이 **엔티티 매니저**다.
- 엔티티 매니저는 엔티티의 상태를 변경하고 영속성 컨텍스트와 상호작용하며 영속 로직을 수행한다.

## 엔티티 매니저의 역할

- `persist`, `merge`, `remove`, `close` 등으로 엔티티의 상태를 변경
- 영속성 컨텍스트의 1차 캐시에서 엔티티 조회
- 쓰기 지연 저장소의 쿼리를 flush해서 DB와 동기화
- JPQL, Native Query로 DB에서 직접 조회

## 엔티티의 4가지 상태

| 상태 | 설명 | 예시 |
|---|---|---|
| **비영속** | 새로 생성됐지만 영속성 컨텍스트와 무관. 메모리에만 존재 | `new Member("산초")` |
| **영속** | 영속성 컨텍스트가 관리. 변경 사항이 자동으로 DB에 반영 | `em.persist()`, `em.merge()`, `em.find()` |
| **준영속** | 관리되다가 분리된 상태. 변경이 DB에 반영되지 않음. 트랜잭션 종료 등으로도 전환 | `em.detach()`, `em.clear()`, `em.close()` |
| **삭제** | 영속성 컨텍스트에서 제거되고 DB에서도 삭제 예정 | `em.remove()` |
