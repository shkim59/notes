# JPA의 ddl-auto 옵션은 각각 어떤 동작을 하고 언제 사용해야 할까?

> 출처: 매일메일(maeil-mail) 면접 질문. 원문을 옮겨 적은 노트라 외부 공개 시에는 직접 다시 정리할 것.

ddl-auto는 스프링 부트에서 Hibernate 같은 JPA 구현체를 쓸 때 데이터베이스 스키마 관리를 제어하는 설정이다. `application.properties` 또는 `application.yml`에서 설정한다.

| 옵션 | 동작 | 사용 환경 |
|---|---|---|
| `none` | 스키마 관련 작업을 하지 않음 | 스키마를 수동으로 관리할 때, 주로 프로덕션 |
| `validate` | 시작 시 엔티티 매핑과 스키마가 일치하는지 검증만 함 | 프로덕션에서 일치 여부 확인 |
| `update` | 매핑과 스키마를 비교해 필요한 부분만 변경. 기존 데이터는 유지 | 개발 중. 프로덕션에서는 예기치 않은 변경에 주의 |
| `create` | 시작 시 기존 스키마를 삭제하고 새로 생성 (데이터 삭제) | 개발 초기. 프로덕션 사용 금지 |
| `create-drop` | `create` + 종료 시 스키마 삭제 | 테스트 환경. 프로덕션 사용 금지 |

## 프로덕션에서 스키마 변경은 어떻게 해야 하나?

- Flyway, Liquibase 같은 마이그레이션 도구로 제어된 방식으로 관리하거나
- 사용자가 없는 시간에 수동으로 스키마 변경 작업을 진행하는 것이 안전하다.
